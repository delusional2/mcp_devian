# mcp_devian

Помощник для художницы, которая продаёт адоптов на DeviantArt и Toyhouse:

- следит за группами DeviantArt и форумами Toyhouse, находит треды, где ищут персов;
- считает рынок: цены, ставки, просмотры и фавы, что продаётся;
- советует, как заработать больше: цена, формат, группы, время, что рисовать;
- ведёт учёт продаж: кто выиграл, оплачено ли, передан ли перс;
- готовит публикацию на DA в группы и папки и отклики на Toyhouse. Отправляет только после её «го» в чате.

Живёт в приложении Claude на маке.

## Установка

1. Скачать файл: **[mcp-devian.mcpb](https://github.com/delusional2/mcp_devian/releases/latest/download/mcp-devian.mcpb)**.
2. Открыть его двойным кликом. Claude Desktop покажет окно установки, нажать «Установить». Первая установка занимает 1–3 минуты: Claude сам скачивает Python и всё нужное.
3. Написать Claude: «давай настроим помощника по адоптам». Можно выбрать **setup** в меню «+». Claude задаст вопросы и сам всё сохранит.

Для режима Toyhouse нужен [Google Chrome](https://www.google.com/chrome/).

Обновление: скачать файл по той же ссылке и открыть так же. Настройки и накопленные данные сохранятся: они лежат в `~/Library/Application Support/mcp_devian/`, а не в папке расширения.

Удаление: сначала сказать Claude «выключи фоновую проверку», потом удалить расширение в настройках Claude. Если удалить сразу, фоновая задача останется в системе. Она не сломается, просто будет тихо ничего не делать.

## Отзывы

Claude иногда, не чаще раза в несколько дней, мягко спрашивает, как ей помощник, и сохраняет ответы. Можно и самой сказать «хочу оставить отзыв» или выбрать **feedback** в меню «+».

Чтобы отправить отзывы автору, сказать Claude «собери мои отзывы»: он покажет текст, его нужно скопировать и переслать. Отзывы лежат только у неё на маке и сами никуда не уходят.

## Что можно просить в чате

- «что нового?» — живые LF-треды с Toyhouse и ставки на её аукционах;
- «проверь тойхаус сейчас»;
- «как мне заработать больше?» — советы с цифрами;
- «хочу продать нового дракона-мотылька, распиши план» — цена, формат, теги, группы, время;
- «посмотри мой пост» + ссылка — что поправить в названии, тегах, описании;
- «что сейчас продаётся?» / «когда лучше выкладывать?»;
- «запиши продажу: Мотылёк №3, $40, купила alice на Toyhouse» / «alice оплатила»;
- «сколько я заработала за месяц?» / «как прошла неделя?»;
- «сколько поставить за нового дракона-мотылька на аукцион? думаю SB $25»;
- «как продаются мои работы?»;
- «добавь группу da-adopts, папки auctions и points adopts»;
- «включи проверку раз в 15 минут» / «выключи»;
- «скрой этот лот»;
- «что со ставками в этом треде на тойхаусе?» + ссылка / «кого сейчас ищут на тойхаусе?»;
- «передай Луну покупателю alice» / «отметь Луну not for sale» — форму заполнит, кнопку жмёшь ты;
- «что не продалось?» / «кто не оплатил?» / «напомни alice об оплате»;
- «пингани пинглист под новой работой» + ссылка;
- «выгрузи продажи в эксель»;
- «сделай превью с водяным знаком».

Если Claude спрашивает разрешение на инструменты чтения (`get_settings`, `findings`, `market`, `forecast`, `advice`), можно выбрать «Разрешать всегда». Эти инструменты ничего не меняют.

## Как читается Toyhouse: два режима

У Toyhouse нет API, и на каждой странице стоит Cloudflare. Поэтому читать нужно настоящим браузером.

**bot — автоматический парсер** (по умолчанию).

- Как работает: свой отдельный Chrome-профиль, проверяет сам по расписанию, даже когда чат закрыт.
- Без входа видит только публичное. Чтобы войти, сказать «войди в аккаунт бота»: откроется окно, логин и пароль вводятся прямо на сайте, в чат их писать не нужно.
- Ограничение: Cloudflare иногда просит у бота галочку «я человек». Тогда приходит уведомление, и галочку нажимает она. Бот эту проверку не обходит.

**chrome — её обычный Google Chrome.**

- Как работает: когда она просит в чате, сервер открывает вкладку в её Chrome, забирает список тредов, закрывает вкладку и возвращает ту, что была открыта.
- Плюсы: она там уже залогинена, Cloudflare видит обычного посетителя.
- Ограничение: работает только по просьбе, в фоне Toyhouse не проверяется.
- Один раз нужно:
  1. В Chrome: меню **Вид → Разработчикам → Разрешить JavaScript из событий Apple** (в английском Chrome: View → Developer → Allow JavaScript from Apple Events).
  2. Когда macOS спросит, разрешить Claude управлять Google Chrome.
- Важно знать: оба разрешения действуют на все вкладки Chrome и на всё приложение Claude, а не только на этого помощника. Выключить: снять ту же галочку в Chrome и убрать Claude → Google Chrome в «Системные настройки → Конфиденциальность и безопасность → Автоматизация».

Другие запросы «Claude хочет управлять…» (Finder, System Events и т. п.) помощнику не нужны, их можно смело отклонять.

DeviantArt в обоих режимах читается без браузера: через официальный API, если она подключила DeviantArt, иначе через RSS папок групп.

### Сколько помощник спрашивает DeviantArt

После серии чтений подряд DeviantArt начинал отвечать 403 («временно не пускает помощника»). С 0.4 все запросы к DeviantArt (ленты, поиск рынка, ставки, статистика, страницы групп) идут через один общий счётчик в базе:

- **Бюджет на скользящий час:** RSS и страницы сайта — не больше 20 запросов, API — не больше 120. Поиск рынка, карточки групп, статистика и чужие аукционы — с низким приоритетом: последние 6 запросов RSS и 30 запросов API за час им не достаются, они остаются лентам и её собственным аукционам. Что не влезло — «остальное в следующий раз».
- **Пауза после 403/429:** весь класс адресов (RSS или API) ждёт 30 минут, потом при повторе 1 ч, 2 ч, 4 ч, не дольше 8 ч. Если DeviantArt прислал Retry-After, ждём не меньше. В этом проходе повторов нет. Чистая проверка снова начинает с 30 минут.
- **Ленты по кругу:** фоновая проверка раз в 15 минут читает 3 ленты, которые дольше всех не читались. Её галерея и папки с её открытыми аукционами идут вне очереди, но одно место всегда остаётся очереди. Проверка по её просьбе читает до 12 лент в том же бюджете.
- **Сначала API:** если DeviantArt подключён, папки групп и галереи читаются через `/gallery/{folderid}` и `/gallery/all`, и UUID работ сохраняются сразу. Описания новых работ дочитываются одним запросом метаданных. RSS остаётся запасным путём: на случай, если DA не подключён, API ответил ошибкой или кончился свой бюджет API на час. После 429 от API в том же проходе RSS не трогаем. Если выдача API для папки не похожа на «сначала новые», эту ленту неделю читаем через RSS.
- **Листаем по делу:** обычно читается одна страница ленты; следующая — только если на ней всё новое. Глубже (лоты, закрывшиеся за 3 дня) лента листается раз в 6 часов и только если в бюджете часа на это хватает. Если бюджет кончился на 2-й странице, уже прочитанное сохраняется.
- **Ставки:** сначала её открытые аукционы, потом (с низким приоритетом) страницы папок и чужие лоты.
- **Условный GET для RSS:** помощник хранит ETag/Last-Modified ленты; ответ 304 означает, что лента не менялась, и считается за ползапроса. Глубокое чтение идёт без него, чтобы 304 первой страницы не прятал закрытия ниже.
- В отчёте проверки и в data_health — одна строка вроде «DeviantArt притормозил чтение лент до 18:40 — читаю через API». Уведомление на маке приходит один раз на серию пауз.

User-Agent честный, браузер не изображаем, адреса не меняем: решение в том, чтобы спрашивать реже.

## Публикация (только по её «го»)

Всё, что уходит на сайты, сначала показывается ей черновиком целиком. Отправляется только после её «го» на этот черновик, и Claude Desktop каждый раз дополнительно спрашивает разрешение.

**DeviantArt: новая работа сразу в группы.**

1. Один раз: «подключи DeviantArt». Откроется страница DeviantArt, нужно нажать «Разрешить». Пароль никуда не вводится.
2. Один раз собрать наборы групп: «добавь в набор „аукционы“ группу da-adopts, папка Auctions».
3. Один раз: «в какие папки моей галереи класть новые работы?» Claude покажет её папки и запомнит выбор.
4. Дальше: «выложи последнюю картинку из Загрузок, название …, описание …, набор „аукционы“». Claude покажет черновик, она пишет «го».

Ещё можно:

- **по расписанию:** «…и выложи завтра в 19:00». После «го» работа уйдёт сама в это время по её часовому поясу. Для этого нужна включённая фоновая проверка;
- **партией:** «выложи эти пять картинок». Получится одно превью и одно «го». Работы уходят по одной, с паузой 1–2 минуты, а лимиты групп считаются по всей партии.

Как это устроено:

- Работа публикуется через официальный API DeviantArt и сразу уходит в группы набора и папки её галереи.
- DeviantArt не сообщает, принята ли работа группой или ждёт голосования, поэтому после отправки стоит заглянуть в группы.
- Лимит: не больше 3 работ в одну группу в день.
- Уже выложенные работы помощник в группы не отправляет. В API для этого есть только метод, который может стереть у работы описание, теги и настройки.

**Защищённое превью.** «Сделай превью с водяным знаком» — уменьшенная копия с её ником (или PNG-логотипом), без EXIF и GPS. Оригинал не трогается, превью ложится рядом как `<имя>-preview`. При публикации на DA можно попросить «выложи с водяным знаком»: в черновике будет видно, что уходит превью, а не оригинал. Стоит один раз проверить на её настоящих файлах (HEIC с айфона, PNG из Procreate).

**Закрыть аукционы, папки, переименование.**

Можно сказать: «закрой все аукционы и переложи их в папку Sold». Claude покажет один черновик на все работы, и после «го» помощник сделает всё сам, по одной работе с паузой 1–2 минуты:

- в названии метка OPEN меняется на CLOSED (или SOLD, если она так скажет), а если метки нет, CLOSED ставится в начало;
- работа перекладывается в папку галереи; если такой папки нет, помощник её создаст, и это будет видно в черновике;
- под работой может появиться её комментарий. Текст пишет она сама, помощник только подставляет ник победителя и сумму ({winner}, {amount});
- победитель записывается в продажи как «ждёт оплаты», без дублей;
- в базе помощника аукцион отмечается закрытым.

Аукционы, у которых срок из описания ещё не прошёл, в «закрой все» не попадают: черновик перечислит их как «ещё идут». Закрыть такой раньше срока можно, только назвав работу, и в черновике у неё будет пометка «⚠ аукцион ещё идёт».

Отдельно можно создать и переименовать папки галереи, разложить по ним работы и переименовать уже выложенные работы.

Как это устроено:

- Всё идёт через официальный API DeviantArt, браузер не нужен. Для папок и комментариев нужны новые права, поэтому после обновления DeviantArt нужно подключить заново: «подключи DeviantArt» и ещё раз «Разрешить».
- Перед правкой названия помощник читает работу и отправляет обратно всё, что API показывает: теги, папки, 18+, комментарии, скачивание. Если что-то из этого прочитать не удалось, работу он не трогает. Работы с лицензией Creative Commons тоже не трогает.
- Чего API не показывает: размер показа и водяной знак DeviantArt. Если она их ставила, после правки они могут сброситься, и такие работы лучше переименовать на сайте. Метки ИИ ставятся по её настройкам. Описание через API не меняется вообще.
- Сбрасывает ли DeviantArt при правке то, что не отправлено, в документации не сказано. Перед первой настоящей правкой стоит один раз проверить на ненужной работе.
- После каждой правки помощник перечитывает работу. Если DeviantArt что-то сбросил, он останавливается и остальные работы не трогает.
- Если название поменяли после черновика, эта работа пропускается. Если ответ DeviantArt потерялся, помощник дальше не идёт и честно пишет, что исход неизвестен.
- Повтор безопасен: новое название, папку, комментарий и продажу второй раз он не делает. Один и тот же комментарий под одной работой никогда не пишется дважды.
- За раз не больше 25 работ. Ход по работам виден в статусе черновика.
- Остановить можно и посреди прохода: «стоп» (отмена черновика). Работу, которая уже в деле, помощник доделает, а следующие не тронет.
- «Закрыть все» берёт аукционы с меткой OPEN и свежие (до 3 недель) без метки, самые новые первыми.

**Toyhouse: отклики в LF-треды.**

1. Один раз (сама, своими словами): шаблон отклика. Например: «Привет! Могу предложить {name} — {url}, цена {price}. {note}».
2. Один раз: список её персов на продажу, со ссылкой, ценой и тегами (вид, стиль).
3. Дальше: «есть треды под моих персов?» → Claude показывает подходящие треды и что в них просит автор. Потом «ответь в этот тред Луной» → черновик → «го».

Как это устроено:

- Отклик отправляется из её Chrome (режим chrome), и помощник проверяет, что пост появился.
- Можно настроить, чтобы текст только вставлялся, а «Post» она нажимала сама.
- Лимиты:
  - один отклик на тред;
  - один перс — не больше 2 тредов в день;
  - не чаще раза в 3 минуты;
  - не больше 8 откликов в день.
- Текст — только её шаблон: правила Toyhouse запрещают тексты, написанные ИИ.

**Риски.**

- Гарантий от бана нет: модераторы обоих сайтов решают сами.
- Чтение (RSS, API, её Chrome по просьбе) почти безопасно.
- Главный риск — отклики на Toyhouse. Новые правила (с 1 декабря 2026) считают спамом повторяющиеся и нерелевантные ответы и одинаковые объявления одного перса, а с сентября работает автоматический антиспам.
- Поэтому отвечать только туда, где перс правда подходит. Начинать отклик с фразы под конкретный тред её словами. В бота на Toyhouse не логиниться.

## Ставки на аукционах

Ставки на DeviantArt — это комментарии под работой. Помощник читает их двумя способами:

- через API, когда DeviantArt подключён: это работает и в фоне, после каждой проверки;
- в её Chrome по просьбе: «что со ставками на этом аукционе?» + ссылка.

Из ставок он собирает:

- сколько ставок и от скольких человек, текущий максимум и у кого, взят ли автобай, закрыл ли автор;
- **уведомление о новой ставке** на её аукцион;
- финальные цены чужих аукционов для прогноза: «аукционы с SB около $10 уходят примерно за $30».

Это разбор комментариев, он может ошибаться: лучше пропустить ставку, чем приписать лишнюю.

## Toyhouse: аукционы, спрос, персы

**Аукционы в тредах.** «Что со ставками в этом треде?» + ссылка — помощник читает тред в её Chrome (или в окне бота) по странице с паузой и разбирает ставки: SB/MI/AB из первого поста, лоты #1, #2, предложения артом и обменом отдельно от денег. Прочитанное запоминается, в следующий раз дочитываются только новые страницы. Победитель её закрытого аукциона сам попадает в продажи «ждёт оплаты». Это разбор постов — стоит глянуть глазами.

Её аукционы-треды (до 5 за раз, по 3 страницы) перечитываются и сами: в режиме bot — в фоне, не чаще раза в полчаса и не дольше 4 минут; в режиме chrome — только когда она просит проверку в чате, её Chrome в фоне не трогается. О новой ставке на её аукционе приходит уведомление. Если Toyhouse просит галочку, остальные треды ждут следующего раза.

**Спрос.** `market:th` — кого ищут в LF-тредах и с какими бюджетами; `market:th_mine` — сколько людей ищут таких, как её персы, и укладывается ли её цена. Это заявленные бюджеты, а не сделки.

**Её персы.** Новый перс, статус продажи («после продажи — not for sale»), передача покупателю, перенос по папкам. Помощник заполняет форму в её Chrome, а «Save» / «Transfer» жмёт она сама — сам он ничего не сохраняет и не отправляет. Перед первым разом нужен разовый осмотр форм: «осмотри форму Toyhouse» для create, edit и transfer.

Что ещё не проверено вживую на её маке: названия полей и адреса форм Toyhouse (сайт не открывался при разработке), подставляется ли картинка в поле файла, как выглядит разметка треда и пагинация. Первый раз стоит сделать всё на одном персе и посмотреть глазами.

## Прогноз по рынку

Мониторинг копит лоты из отслеживаемых папок:

- стартовые цены (SB) аукционов и фикс-цены;
- тип лота и теги;
- когда лот появился и когда закрылся.

`market:forecast` находит похожие лоты по словам (вид, стиль) и показывает:

- обычный диапазон цен;
- сколько похожих сейчас открыто;
- какая доля закрывается и как быстро;
- где её цена среди похожих.

Ограничения честные: финальных ставок не видно, «закрыт» не всегда значит «продан», данные копятся с момента установки. Чтобы прогноз был точнее, стоит добавить пару крупных групп адоптов «только для рынка»: из них не приходят уведомления, но они дают цены.

Claude пересказывает прогноз бережно: диапазоны вместо приговоров и мягкие варианты вместо критики.

**Рынок шире папок.** `market:search` ищет чужие лоты её ниши поиском DeviantArt (только данные, без уведомлений); `market:groups` — насколько живы группы и подходят ли под её нишу; `market:buyers` — кто ставит в её нише (никому не пишем); `market:norms` — как оформляют лоты на рынке (доли и n). `forecast:health` показывает, на каких данных стоит аналитика, а `forecast:explain` — как помощник понял конкретный лот.

## Продажи и советы

Помощник ведёт **учёт продаж**. Победителей её аукционов на DA он записывает сам. Продажи с Toyhouse и из личных сообщений она называет в чате; со ссылкой на её тред-аукцион Toyhouse (и номером лота) запись не задвоится с автоматической. У каждой продажи есть статус: «ждёт оплаты», «оплачено», «перс передан», «готово». Из учёта считается доход по валютам, площадкам и форматам.

**Советы** (`advice:tips`) строятся по её лотам и рынку. У каждого совета есть цифры и пометка, насколько он надёжен:

- цена: аукционы уходят намного выше старта, значит, старт можно поднять; ставок мало — снизить порог;
- автобай: его берут сразу или до него никогда не доходят;
- в какие группы её лоты собирают больше ставок, в какой день и час выкладывать;
- какие виды и стили сейчас в спросе и где мало предложения;
- какие персы давно не проданы и в каких LF-тредах их ищут;
- какие продажи не оплачены несколько дней.

**Прогноз по нише** (`forecast:niches`, `forecast:price`, `forecast:accuracy`). Он считает, что продаётся у продавцов её уровня, а не у всего рынка: высокие старты известных авторов к новичку не переносятся.

- **Продано** — это закончившийся аукцион, на который поставил хотя бы один человек. По каждому виду, стилю и теме считается доля таких аукционов и число похожих лотов за 2 недели.
- **Свежие лоты весят больше:** вес лота уменьшается вдвое каждые 14 дней.
- **После праздника тема считается отдельно:** например, тёмная тема после Хэллоуина.
- **Маленькие выборки не выдаются за правду:** 2 продажи из 2 не превращаются в «100%».
- **Старт аукциона** выбирается по наибольшей ожидаемой сумме с учётом шанса, что ставок не будет.
- **Проверка на прошлом:** каждый прошлый лот предсказывается только по тому, что было известно до его публикации. Потом показывается, как часто такие прогнозы сбывались.
- **Ответ не меняется без новых данных.** В нём всегда видно, на скольких лотах он основан.

**План нового адопта** (`advice:plan`) включает цену по рынку, формат, заготовку названия и тегов, группы, время и подходящие LF-треды. Название и описание она пишет сама.

**Отчёт недели** приходит уведомлением раз в неделю: по умолчанию в воскресенье в 19:00 по её времени. В отчёте доход против прошлой недели, неоплаченное и три главных совета.

Если DeviantArt подключён, раз в час помощник снимает просмотры, фавы и комментарии лотов. Это нужно для советов «что рисовать» даже без ставок.

**Непроданное** (`advice:unsold`): что висит без ставок и варианты с цифрами из её данных и рынка — снизить старт, OTA, набор, перевыложить в лучшее время.

**Сроки аукционов** (`da_auctions:deadlines`): когда кончается каждый её открытый аукцион, если срок написан в описании («ends 03.11 20:00 EST», «72h auction»). Неясный срок помощник не угадывает, а так и говорит. За 3 часа до конца и когда срок прошёл, а лот не закрыт, приходит уведомление на маке — по разу на лот.

**Оплата.** `sales:unpaid` — кто не оплатил дольше 3 дней. Напоминание — комментарий под её работой, только её шаблоном (`set_template`), черновиком и по её «го»; не чаще раза в 3 дня и не больше двух на продажу (если ответ DeviantArt потерялся, напоминание считается отправленным). Если покупатель или сумма записаны по ставкам и не проверены, напоминание не готовится. Раз в сутки приходит одно уведомление «Не оплачено: N — спроси Claude»; черновики напоминаний сами не готовятся.

**Пинглист.** Кто сам написал «ping me / add me to your pinglist» под её работами (помощник видит это, когда читает комментарии под её аукционами), и кого она добавила сама. Пинг под новой работой — её шаблон и до 10 @ников в комментарии, до 50 человек под одной работой, пауза 2,5–4 минуты между комментариями, черновиком и по «го». Если кто-то вышел из пинглиста, пока черновик ждал, его комментарий пропускается целиком. Сработает ли упоминание @ник в комментарии через API как уведомление, надо один раз проверить на её аккаунте.

Комментарии от её имени ограничены: не больше 20 в сутки вместе с комментариями при закрытии аукционов, из них пингов — не больше 10. Настройкой (`da_comments_per_day`, `da_pings_per_day`) их можно только уменьшить. Один и тот же текст под одной работой дважды не пишется; если ответ DeviantArt потерялся, повтора нет, а статус честно «неизвестно».

**Выгрузка** (`sales:export`): продажи (и лоты) в CSV для Excel/Numbers в Загрузки (если macOS туда не пускает — в папку помощника).

**Обновления.** Если вышла новая версия, это будет строкой в настройках и один раз уведомлением на маке.

## Что выяснили про площадки

### DeviantArt

- **Мониторинг групп работает без логина.** У каждой папки группы есть RSS: `backend.deviantart.com/rss.xml?type=deviation&q=gallery:<группа>/<номер>`. Порядок в нём не гарантирован, поэтому дедуп идёт по `deviationid`. robots.txt просит `Crawl-delay: 1`, поэтому между лентами пауза 2–4 с; сколько лент за проход и сколько запросов в час — см. «Сколько помощник спрашивает DeviantArt».
- **Много чтений подряд DeviantArt не любит.** В 0.3 каждая папка читалась каждые 15 минут, и после серии таких чтений DeviantArt отвечал 403. Теперь у помощника общий лимит на час (20 запросов к лентам, 120 к API), ленты читаются по три за раз по кругу, обычно по одной странице, и сначала через официальный API. Если DeviantArt всё же просит подождать, помощник ждёт от 30 минут до 8 часов и сам ничего не повторяет.
- **Рассылка в группы есть в официальном API.** У `POST /stash/publish` есть параметры `groups[]` и `group_folders[]` ([stash/publish](https://deviantart.readme.io/reference/stash_publish.md)). Вживую не проверялось, это задача фазы 2.
- **Лимиты задаёт каждая группа:** обычно до 10 сабмитов в день. Если сабмит ушёл на голосование и решения нет 14 дней, он сгорает ([справка DA](https://www.deviantartsupport.com/en/article/how-do-group-admins-vote-on-submissions)).

### Toyhouse

- **API для контента нет.** OAuth отдаёт только `/me`.
- **Cloudflare на каждой странице.** HTTP-клиенты и Chrome без окна не пускают.
- **Доски:** [Adoption Center](https://toyhou.se/~forums/13.adoption-center) (13), Design Marketplace (5866), Art Marketplace (71). Номера сняты с меню форума.
- **С 1 декабря 2026 действует новый Code of Conduct** ([анонс](https://toyhou.se/~forums/18.announcements/869575.th-october-2026-updates-new-code-of-conduct)). Спамом считаются повторяющиеся отклики и одинаковые объявления одного перса. С сентября работает автоблок. Отсюда правило для будущей фазы 2: отклики только после её «го», с лимитами.

### Claude Desktop

Проверено на 01.11.2026:

- поле `instructions` MCP-сервера модели не передаётся, поэтому правила настройки и тон приходят в ответе `get_settings` (его описание просит вызывать его первым), а правило «только после её «го»» — ещё и в описаниях `submit_draft` и `schedule_draft`;
- имена, описания и схемы всех инструментов уходят в Claude с каждым сообщением. Поэтому инструментов 27, а не 86: похожие действия собраны в один инструмент с параметром `action` (в README и ответах помощника это записано как `tool:action`, например `sales:unpaid`). Описания короткие, длинные правила — один раз в `get_settings`, из показанных схем убраны служебные `title`, «или null» и значения по умолчанию (кроме `true`). Всё вместе — около 15 тыс. знаков вместо 44 тыс. (плюс 12 тыс. знаков `outputSchema`, которых больше нет); тест `tests/test_token_diet.py` не даст вырасти больше 16 тыс. знаков и 40 инструментов;
- длинный ответ инструмента обрезается примерно на 3500 знаках с пометкой, сколько строк не показано. Черновики и текст отзывов не обрезаются никогда: она должна видеть их целиком;
- формы с вопросами (elicitation) пока не показываются;
- вызов инструмента обрывается примерно через 60–240 с, поэтому проверка идёт в фоне: `check:run` ждёт до 45 с, остальное узнаётся через `check:status`.

## Устройство

| Часть | Чем |
|---|---|
| Установка | `.mcpb` с `server.type: "uv"`: Claude Desktop сам ставит uv, Python и зависимости по `uv.lock` |
| Настройки | `settings.json` в папке данных, заполняются через `update_settings` по ответам в чате |
| DeviantArt | RSS папок групп, её галереи и выбранных художников |
| Toyhouse | её Chrome через Apple Events (`her_chrome.py`) или Playwright с отдельным профилем (`toyhouse.py`) |
| Хранилище | SQLite в папке данных |
| Фон | launchd LaunchAgent, включается из чата (`set_background_checks`) |
| Уведомления | macOS и (по желанию) Telegram |
| Прогноз | `market.py`: перцентили цен похожих лотов, доля и скорость закрытия |
| Советы | `advisor.py` (правила с цифрами), `sales.py` (учёт продаж), `taxonomy.py` (виды и стили), `enrich.py` (просмотры и фавы через API) |
